# video-upconv

実写の mp4 を、フレーム補間（RIFE）で 120fps 前後に、超解像（Real-ESRGAN 系）で 4K に変換する Docker 環境。
変換の前段として、動画に映る顔を別の画像の顔に交換することもできる。

- 作成日：2026-10-03
- 動作確認環境：Windows + WSL2（Ubuntu 26.04）、Docker Desktop 4.72.0、RTX 3060 Ti 8GB（ドライバ 595.95）、i7-10700F
- 作成者：Claude Code（Opus 5.5）

## 構成

処理の本体は `upconv.py` である。
VapourSynth で次の処理を組み、y4m 形式で ffmpeg へ渡して `hevc_nvenc` で符号化する。
音声は元の動画から無変換でコピーする。

1. 動画を BestSource で読み込み、RGB 半精度（RGBH）に変換する
2. vsrife で RIFE による補間を行う。元の fps を整数倍して目標 fps に最も近づける（23.976fps なら 5 倍で 119.88fps、29.97fps なら 4 倍）
3. vsrealesrgan で超解像を行い、目標の高さに合わせて縮小する
4. YUV 4:2:0 10bit の BT.709 に変換し、HEVC Main10 で出力する

補間と超解像は Torch-TensorRT で実行する。
TensorRT の推論用エンジンは、入力解像度とモデルの組み合わせごとに初回だけビルドされ、`cache/trt/` に保存される。

顔の交換は `face_swap.py` が別のプロセスで行い、`upconv.py` に渡す中間動画を作る。
推論には ONNX Runtime の CUDA 実行プロバイダを使う。
詳しくは「顔交換（前段）」の節に書く。

## 前提

- Docker Desktop の WSL integration が有効で、WSL から `docker` が使えること
- コンテナから GPU が見えること（`docker run --rm --gpus all ubuntu nvidia-smi` で確認できる）

## ビルド

```sh
cd video-upconv
mkdir -p work cache  # 動画とキャッシュの置き場。git では管理しない
docker compose build
```

顔交換の依存を足す前のイメージは約 18.5GB だった。
足した後の大きさは測っていない。
TensorRT のライブラリ（約 3.7GB）を `pypi.nvidia.com` から取得するので、回線によっては 1 時間以上かかる。

`upconv.py` と `face_swap.py` は `compose.yaml` がコンテナにマウントするので、スクリプトを修正してもイメージを再ビルドする必要はない。
`Dockerfile` が変わったときは再ビルドが要る。
顔交換の依存が入っていないイメージを使っている場合も、`face_swap.sh` を使う前に再ビルドする。
`Dockerfile` では顔交換の依存を torch とモデルの層より後ろに置いているので、それらの層のビルドキャッシュが残っていれば、取得し直すのは顔交換の層だけで済む。

## 使い方

`upconv.sh` に入力と出力のパスを渡す。
パスは WSL から見えるものなら何でもよい（`/mnt/d/...` のような Windows 側のドライブも可）。

```sh
./upconv.sh /mnt/d/videos/input.mp4 /mnt/d/videos/output.mp4
```

`upconv.sh` は、入力ファイルのディレクトリを読み取り専用で、出力ファイルのディレクトリを書き込み可能でコンテナにマウントしてから `upconv.py` を実行する。
コンテナには `compose.yaml` が `work/` と `cache/` しかマウントしないので、`docker compose run` を直接使う場合は動画を `work/` に置く必要がある。

既定では 120fps 前後への補間と、高さ 2160 への拡大を両方行う。
長い動画は、`--frames` で一部だけを変換して画質と速度を確かめてから全体を変換するとよい。

```sh
# 1000 フレーム目から 240 フレームだけ試す
./upconv.sh input.mp4 trial.mp4 --start 1000 --frames 240

# 補間だけ行う
./upconv.sh input.mp4 out.mp4 --height 0

# 拡大だけ行う（1440p）
./upconv.sh input.mp4 out.mp4 --target-fps 0 --height 1440

# 720p を 4 倍モデルで 4K にする
./upconv.sh input.mp4 out.mp4 --sr-model realesr_general_x4v3

# 4:3 の映像を 16:9 に引き伸ばして 4K にする（3840x2160）
./upconv.sh input.mp4 out.mp4 --aspect 16:9
```

主なオプションは次のとおりである。
全オプションは `./upconv.sh --help` で表示できる。

| オプション | 既定値 | 意味 |
|---|---|---|
| `--target-fps` | 120 | 目標 fps。0 で補間しない |
| `--rife-model` | 4.25 | RIFE のモデル |
| `--sc-threshold` | 0.15 | シーンチェンジとみなす隣接フレームの輝度差（0〜1） |
| `--no-sc` | なし | シーンチェンジ検出を無効にする |
| `--height` | 2160 | 出力の高さ。0 で拡大しない |
| `--aspect` | なし（元の比率） | 出力のアスペクト比（`16:9` や `2.39`）。高さはそのままで、幅を引き伸ばして合わせる。切り抜きや黒帯は付けない |
| `--sr-model` | OpenProteus_Compact_2x | 超解像のモデル |
| `--order` | vfi-first | 補間と拡大の順序 |
| `--cq` | 20 | NVENC の品質値。小さいほど高画質で大きいファイルになる |
| `--preset` | p5 | NVENC のプリセット。p1 が最速、p7 が最高画質 |
| `--overwrite` | なし | 出力ファイルが既にあれば上書きする。付けなければ、変換を始める前にエラーで終了する |

## 顔交換（前段）

`face_swap.sh` は、動画に映る顔を `--ref` の画像の顔に交換し、`upconv.sh` に渡す中間動画を作る。

フレームごとに InsightFace の buffalo_l で顔を検出し、inswapper_128 で交換する。
`--ref` だけを指定したときは、検出した顔をすべて交換する。
`--target` に人物の画像を渡すと、その人物と同一人物と判定した顔だけを交換する。

同一人物の判定は、顔の埋め込み（顔の特徴を表すベクトル）の類似度だけで行う。
検出した顔の埋め込みと `--target` の顔の埋め込みとのコサイン類似度が `--threshold` 以上なら同一人物とみなし、`--threshold` 未満の顔には手を加えない。
性別やマスクの有無は判定していない。

### モデルの入手

交換モデルの `inswapper_128.onnx`（約 555MB）は自分で取得して、`cache/faceswap/` に置く。
次の URL は 2026-10-03 に取得できることを確かめた。

```sh
mkdir -p cache/faceswap
curl -L -o cache/faceswap/inswapper_128.onnx \
  https://github.com/facefusion/facefusion-assets/releases/download/models-3.0.0/inswapper_128.onnx
```

検出と埋め込みの buffalo_l（約 289MB の zip）は、初回の実行時に insightface が GitHub の InsightFace のリリースから取得し、`cache/faceswap/models/buffalo_l/` に展開する。

### 使い方

`face_swap.sh` で中間動画を作り、それを `upconv.sh` に渡す。
交換で入れる顔の画像を `--ref` で渡す。
動画に複数の人物が映っていて、そのうちの 1 人だけを交換したいときは、その人物の画像を `--target` で渡す。

```sh
# 映っている顔をすべて face.png の顔にする
./face_swap.sh input.mp4 mid.mp4 --ref face.png
./upconv.sh mid.mp4 output.mp4

# person.png の人物の顔だけを face.png の顔にする
./face_swap.sh input.mp4 mid.mp4 --ref face.png --target person.png

# 1000 フレーム目から 240 フレームだけ試す。中間動画はその範囲だけになるので、upconv.sh には範囲を渡さない
./face_swap.sh input.mp4 trial_mid.mp4 --ref face.png --start 1000 --frames 240
./upconv.sh trial_mid.mp4 trial.mp4

# 画像を複数渡す
./face_swap.sh input.mp4 mid.mp4 --ref front.png,side.png --target person1.png,person2.png
```

`face_swap.sh` は `upconv.sh` と同じく、入力と出力のディレクトリをコンテナにマウントする。
`--ref` と `--target` の画像のディレクトリも読み取り専用でマウントする。
どちらも `--ref 値` と `--ref=値` のどちらの書き方でもよい。

`--ref` と `--target` の画像に複数の顔が写っているときは、最も大きく写った顔を使う。
顔が画像いっぱいに写った画像からは、顔を検出できないことがある。
insightface に同梱の、顔だけを切り抜いた 112x112 の画像（`Tom_Hanks_54745.png`）からは顔を検出できず、周囲に余白を足して一辺を 2 倍にすると検出できた（2026-10-04）。

主なオプションは次のとおりである。
全オプションは `./face_swap.sh --help` で表示できる。

| オプション | 既定値 | 意味 |
|---|---|---|
| `--ref` | なし（必須） | 交換で入れる顔の画像。カンマ区切りで複数渡せる。複数のときは、全画像の顔の埋め込みの平均を交換元にするので、同じ人物の画像を渡す |
| `--target` | なし | 交換したい人物の画像。カンマ区切りで複数渡せる。指定すると、この人物と同一人物と判定した顔だけを交換する。複数のときは、全画像の顔の埋め込みの平均と比べる。省略すると、検出した顔をすべて交換する |
| `--threshold` | 0.35 | `--target` の人物と同一人物とみなすコサイン類似度の下限（-1 から 1）。上げると交換する顔が減る。`--target` と一緒に指定する。`--target` なしで指定するとエラーで終了する |
| `--det-thresh` | 0.5 | 顔とみなす検出スコアの下限（0 より大きく 1 より小さい値）。下げると検出する顔が増えるが、顔でないものを検出することも増える。既定値は insightface 0.7.3 の `FaceAnalysis.prepare` の既定値と同じである |
| `--det-size` | 640 | 顔検出の入力の一辺（32 の倍数）。大きいほど小さく映った顔を検出できるが遅くなる |
| `--start`、`--frames` | 0、0 | 処理を始めるフレーム番号と、処理するフレーム数。`--frames 0` は最後まで |
| `--qp` | 0 | 中間動画の libx264 の量子化値（0 から 63）。0 は可逆。上げるとファイルが小さくなり画質が落ちる |
| `--allow-cpu` | なし | CUDA で推論できないときに CPU で続行する。付けなければエラーで終了する |
| `--overwrite` | なし | 出力ファイルが既にあれば上書きする。入力と同じファイルを出力に指定した場合は、付けても拒否する |

`--det-thresh` は動画のフレームに対する値である。
`--ref` と `--target` の画像には、`--det-thresh` と 0.5 の小さいほうを使う。
0.5 以上の顔が画像にあれば、その中で最も大きい顔を使う。

### 終了時の出力としきい値の決め方

終了時に、検出と交換の集計を標準エラーに出す。
`--det-thresh` と `--threshold` は、短い範囲（`--start` と `--frames`）で試して、この値を見て決める。
次は、6 人が映る 640x480 の 96 フレームの映像で、そのうちの 1 人を `--target` にしたときの出力である（画像のパスは省略した）。

```
ref   : /ref/.../face.png faces=1 used=159x216 det_score=0.860
target: /ref/.../person.png faces=1 used=110x151 det_score=0.871
input : 640x480 24.000fps 96f
swap  : faces with similarity to --target >= 0.35
done in 0.3 min  frames=96 face_frames=96 faces=483 swapped=96
det_score : n=483 min=0.500 median=0.898 max=0.929  (--det-thresh 0.5)
similarity: n=483 min=-0.111 median=0.001 max=0.986  (>= --threshold 0.35: 96)
frame_best: n=96 min=0.980 median=0.982 max=0.986  (>= --threshold 0.35: 96)
```

| 項目 | 意味 |
|---|---|
| `ref`、`target` の行 | 画像ごとの、検出した顔の数（faces）、使った顔の大きさ（used）と検出スコア（det_score） |
| `frames` | 処理したフレーム数 |
| `face_frames` | 顔を 1 つ以上検出したフレーム数 |
| `faces` | 検出した顔の延べ数 |
| `swapped` | 交換した顔の延べ数 |
| `det_score` | 検出した顔の検出スコアの個数（n）、最小、中央値、最大 |
| `similarity` | 検出した顔と `--target` との類似度の個数、最小、中央値、最大と、`--threshold` 以上だった数。`--target` を指定したときだけ出る |
| `frame_best` | 顔を検出したフレームごとの、類似度の最大についての同じ集計。`--target` を指定したときだけ出る |
| `failed` | 交換の対象にしたが、inswapper が元のフレームへ貼り戻せなかった顔の延べ数。1 つ以上あるときだけ出る |

`--target` を指定しないときは、`swapped` は `faces` から `failed` を引いた数になる。

顔が映っているのに `face_frames` や `faces` が少ないときは、顔を検出できていない。
`--det-thresh` を下げて、`faces` が増えるかを見る。
小さく映った顔なら `--det-size` を上げる。
`--det-thresh` を下げると、顔でないものも検出して交換する。
`--target` を指定していれば、顔でないものは類似度が `--threshold` に届かない限り交換されない。

`--target` を指定して `swapped` が 0 か少ないときは、`frame_best` を見る。
複数の人物が映る動画では、`similarity` は別人の顔を含むので中央値が 0 付近になる。
`frame_best` は、目的の人物が映っているフレームでは、その人物の類似度になる。
`--threshold` は、`frame_best` の最小より低く、別人の類似度より高い値にする。
目的の人物が映っていない動画では、`frame_best` の最大も低い。
上と同じ映像で、映っていない人物を `--target` にしたときの `frame_best` は、最小 0.060、中央値 0.072、最大 0.141 だった。

### 中間動画の形式

中間動画は、libx264 の可逆圧縮（`-qp 0`）、YUV 4:4:4 の 10bit、BT.709 のタグ付きで書く。
超解像の前に圧縮ノイズを足さないためで、8bit の RGB のフレームを 10bit の YUV 4:4:4 にすると、復号して RGB に戻したときに元の画素値と一致する（合成映像で確かめた）。
可逆なのでファイルは大きい。
容量が足りないときは `--qp` を上げる。

フレームの読み書きには ffmpeg を使う。
fps は元の動画の有理数（24000/1001 など）をそのまま使い、音声は元の動画から同じ範囲を無変換でコピーする。
色空間のタグが無い入力は、`upconv.py` と同じく、高さが 720 以上なら BT.709、それ未満なら BT.601 として読む。
回転のメタデータが付いた入力は、回転を適用した向きで処理する。
中間動画には回転した後の映像を書き、回転のタグは付けない。

フレーム数は、処理を始める前に入力の映像パケットを走査して数える（復号はしない）。
mp4 のエディットリストが捨てるフレームは数に入れないので、`--start` のフレーム番号は `upconv.py` と同じ数え方になる。
mp4 のようにコンテナがフレーム数を持つ形式で、読めたパケットがそれより少なければ、入力が途中で切れているとみなして、モデルを読み込む前にエラーで終了する。

### 制限

- 顔を検出できなかったフレームには手を加えない。検出はフレームごとに独立で、前後のフレームの結果は使わない
- `--target` を指定したとき、類似度が `--threshold` より低く出た本人の顔は交換されず、高く出た別人の顔は交換される
- `--target` を指定しないとき、顔でないものを顔として検出すると、そこにも顔を貼る
- inswapper_128 は顔を 128x128 で生成してから元の位置に貼り戻す。大きく映った顔では、顔の部分の解像感が周囲より落ちる
- フレームは 8bit の RGB で処理する。10bit や HDR の入力は 8bit に落ち、トーンマッピングは行わない
- `--start` はフレームを数えて位置を決めるので、先頭から `--start` までを復号して読み飛ばす時間がかかる
- 入力が途中で切れていることを検出できるのは、mp4 のようにコンテナがフレーム数を持つ形式だけである。mkv のような形式では、読めたところまでを正常な入力として処理する

### 確認状況

2026-10-04 に、コンテナの中で CUDA で実行して確かめた。
映像は、insightface に同梱の画像 `t1.jpg`（6 人が写っている）から作った、640x480、24fps、96 フレームのパンする映像である。
顔の大きさは、幅 60 画素、高さ 80 画素前後である。
6 人のうち両端の 2 人は、パンで顔がフレームの外に出る時間がある。
交換の前後で画素が変わった範囲は、入力と中間動画を同じ方法で復号して比べた。

| 指定 | faces | swapped | 画素が変わった範囲 |
|---|---|---|---|
| `--ref` のみ | 483 | 483 | 検出した 483 の顔のすべてとその周囲だけ |
| `--ref` と `--target`（映っている 1 人） | 483 | 96 | その 1 人の顔とその周囲だけ（96 フレームすべて） |
| `--ref` と `--target`（映っていない人物） | 483 | 0 | なし（全フレームが入力と一致） |

`--target` の画像は、映像の元にした画像から切り抜いたものである。
別の写真を `--target` にしたときの類似度は測っていない。

`--det-thresh` を変えたときの検出数は次のとおりだった。
「顔でない検出」は、6 人の顔のどの位置とも重ならない検出の延べ数である。

| `--det-thresh` | faces | 顔でない検出 | 顔でない検出のスコアの最大 |
|---|---|---|---|
| 0.9 | 208 | 0 | |
| 0.5 | 483 | 0 | |
| 0.3 | 494 | 0 | |
| 0.1 | 593 | 87 | 0.227 |

0.1 では、`--target` を指定しない実行で顔でない検出もすべて交換の対象になり、6 人の顔から離れた位置の画素が変わった。
0.02 では 1 フレームあたり 80 前後を検出し、その一部は貼り戻せずに `failed` に数えられた。

#### マスクを着けた顔

実物のマスクを着けた顔では確かめていない。
代わりに、同じ画像の 6 人の顔の、鼻から顎までを単色で塗りつぶした映像（擬似マスク）で測った。
擬似マスクは実物のマスクと見え方が違うので、次の値が実物のマスクにも当てはまるかは分からない。

フレームの外に出ない 4 人についての値は次のとおりである。
類似度は、同じ人物の塗りつぶす前の画像を `--target` にしたときの値である。

| 映像 | 検出できたフレーム | 検出スコアの中央値 | 類似度の中央値 |
|---|---|---|---|
| 塗りつぶす前 | 4 人とも 96 / 96 | 0.842〜0.915 | 0.977〜0.982 |
| 擬似マスク | 4 人とも 96 / 96 | 0.757〜0.829 | 0.639〜0.689 |

- 擬似マスクでは、検出スコアも類似度も下がったが、既定の `--det-thresh` と `--threshold` のままで検出と交換が行われた。4 人の類似度の最小は 0.624 だった
- 擬似マスクの映像に `--ref` だけを指定すると、検出した 469 の顔がすべて交換された。塗りつぶす前の 1 人を `--target` にすると、その 1 人だけが 96 フレームすべてで交換された
- 擬似マスクの映像では、顔でない検出が `--det-thresh` 0.3 で 11（スコアの最大 0.432）、0.1 で 138 あった

`--ref` に複数の画像を渡したときの交換元は、別人の画像 2 枚で確かめた。
交換後の顔と各画像の顔との類似度の中央値は 0.585 と 0.606 で、1 枚だけを渡したときの 0.881 より低く、2 人の中間の顔になった。
同じ人物の画像を複数渡したときに、1 枚のときより良くなるかは確かめていない。

後段の `upconv.sh` には、`--target` を指定して作った中間動画を `--height 0 --target-fps 0` で渡し、96 フレームと音声が出力されることを確かめた。

## 速度の実測値

2026-10-03 に、RTX 3060 Ti で合成映像（ffmpeg の testsrc2）を 48 フレーム変換して測った値である。
実写の動画では、デコードや符号化の負荷が変わるので数値も変わりうる。

| 処理 | 出力 | 出力側の処理速度 |
|---|---|---|
| 1080p 23.976fps を 5 倍に補間 | 1080p 119.88fps | 53.71 fps |
| 上の補間の後、OpenProteus_Compact_2x で 4K に拡大 | 2160p 119.88fps | 10.44 fps |

2 行目の構成では、動画 1 秒分（119.88 フレーム）の変換に約 11.5 秒かかる。
10 分の動画ならおよそ 2 時間である。
変換中に 20 秒間隔で測った VRAM の使用量は約 4.9GB だった。変換後は約 2.1GB に戻ったので、この 2.1GB は他のアプリケーションが使っていた分と考えられる。

## 注意点

### 処理順序

既定の `vfi-first` は、元の解像度で補間してから拡大する。
拡大するフレームが 5 倍に増えるので遅くなるが、補間を 4K で行わずに済むので VRAM が少なくて済む。

`sr-first`（先に拡大する）で 4K のまま補間すると、RIFE の 4K 用エンジンをビルドしている途中で WSL ごと応答しなくなった（2026-10-03）。
VRAM 不足が原因と推測しているが、確かめていない。
そのため、`sr-first` で 1440p を超える補間は `--force` を付けない限り拒否するようにしている。

### シーンチェンジ検出

vsrife の標準のシーンチェンジ検出は、VapourSynth の misc プラグイン（`misc.SCDetect`）を使う。
PyPI 版の VapourSynth R80 には misc プラグインが含まれていない。
そのため、`upconv.py` の `sc_detect` で同じ判定を `std.PlaneStats` を使って行っている。

カットを含む合成映像で確かめたところ、カット位置の隣接フレーム差は 0.543、通常の動きは 0.016〜0.026 だった。
検出を有効にすると、カットの直前に生成されるフレームはすべてカット前のフレームの複製になり、前後のシーンが混ざったフレームは生成されなかった。
フラッシュなど急な明るさの変化をカットと誤検出して動きがカクつく場合は `--sc-threshold` を上げ、カットで前後のシーンが混ざる場合は下げる。

### 初回実行

入力の解像度が変わるたびに、TensorRT のエンジンがビルドされる。
2 回目以降は `cache/trt/` のエンジンが再利用される。
ビルドが途中で止まって 0 バイトのエンジンファイルが残った場合は、次の実行の前に削除する。

```sh
find cache/trt -size 0 -delete
```

### 出力形式

3060 Ti の NVENC は AV1 の符号化に対応していないので、HEVC で出力している。
`-tag:v hvc1` を付けているので、QuickTime などの Apple 製プレイヤーでも再生できる。
